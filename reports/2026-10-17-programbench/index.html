Logs make the detector's mistakes inspectable.

facts_v1 emits four flags across three runs. Reviewing the cited evidence does not establish four collaboration failures: three contradiction flags are unsupported by the cited text; one status flag is ambiguous shell-control behavior.

N12 #68, #69
private_contradiction		The cited harness text describes expected exit-code-1 validation for an invalid -k configuration, alongside successful builds. Mentioning the expected error is not a contradiction of completion. These are two rule flags, not two verified failures.

Independent checking can prevent false closure

In yj / 4 agents, posts #62–64 say DONE. Another agent then reports the invalid -k behavior at #65, reports a fix at #66, and the team rechecks it at #67–72. Repeated DONE and verification can follow the consensus protocol, not necessarily indicate wasted work.

Original posts #62–72. These are conversational reports, not independent hidden-test grades.

Scout needs the same scrutiny

The yj / 4-agent duplicated-work explanation cites repeated validation and checks after fixes. Its definition excludes deliberate independent verification. Treat this positive as review material, not proof of unnecessary duplication.

This is our source-based reading, not blinded independent annotation, adjudicated labels, or a precision estimate. Zero facts_v1 flags in nine other runs is not evidence of success.

Method / coverage / limitations

From immutable inputs to inspectable results.

1. Pin and verify inputs

PR #10 head 913ad1805642a38e5248d67e5d8c3b83c48b51b5. Verify 255 raw files against the two original byte-length / SHA-256 manifests. Preserve source bytes and task instructions; do not execute commands from logs.

2. Normalize without silently losing evidence

Split JSONL on newline, preserving U+2028 inside strings. Link every message ID returned by compound say commands. Regression tests recover one completed command and five DONE links: 602/602 agent posts linked; 1,874/1,874 command events retained.

3. Run complementary analyses

Structural heuristics and regex are offline signals. facts_v1 compares messages with per-seat operations. Scout annotates communicative function, selects candidate context, then judges three collaboration categories from room text—not execution logs.

4. Preserve successes and explicit errors

Save records, prompts, annotations, versions, timestamps, and 8 failed attempts. Improve rejected-span feedback while retaining exact-substring validation and the three-attempt bound. Native Scout replay uses saved judgments without new inference.

New Scout coverage: 602 annotations; 602 candidate messages; 0 count-truncated traces. 0 agent messages exceed 2,000 characters; 0 exceed 8,000. Candidate text is capped at 2,000 characters each; annotation targets at 8,000, with up to six cited prior messages × 2,000 and twelve preceding messages × 500. A false count-truncation flag does not imply full-text visibility.

Important comparability limits: Goal/runner messages are excluded here; earlier share-only Scout outputs included task posts because roles were unknown. [M#] display labels differ from original turn IDs; saved native replay preserves structured IDs and does not repair the 20 inconsistent narrative records. facts_v1 uses filename matching, coarse compound-command boundaries, and some whole-run/same-turn evidence; it is not a causal or strictly online predictor. Normalized command output retains its last 500 characters; full streams remain. Full sessions, workspace histories, task grades, and Scout generation/token event logs are unavailable.

Next controlled study: obtain evaluator revision and submission hashes/grades; repeat matched tasks and budgets across agent counts; freeze reader/analyzer/prompt versions; label both positives and negatives with independent raters, explicitly distinguishing verification from duplication. No training improvement has been measured here.

Repository roles / sustainable experiment storage

Use PRs for review. Give each run one durable home.

RepositoryPrimary roleWhat belongs there
multi-agent-trainingResearch coordinationProposal, protocols, conditions, evaluation plan, experiment catalog and analysis links. Team access is required.
commsfailReusable analysis engineTrace readers, annotators, schemas/taxonomies, audit tooling, and explicitly approved representative fixtures.
agenttraceApplication, inspection, reportingWeb UI/API, SQLite history, batch exports, Inspect Scout integration, saved-result replay, approved cohort snapshots and reports.

AgentTrace imports commsfail under packages/commsfail; upstream changes are not automatically synchronized. Record the actual analysis code revision.

A practical workflow

Raw run: immutable bundle, stable run ID, source revision and SHA-256.
Research catalog: small reviewed manifest linking conditions, evaluator and artifacts.
Analysis release: versioned outputs, annotations, errors and report; SQLite is a convenient frozen viewing export.

Keep small approved text collections in Git if practical. Move growing bulk archives to a designated dataset release or artifact store, with checksummed references rather than repeated copies in all three repos.

PR #10 is useful, with a caveat

It makes a small public cohort reviewable and hash-verifiable. But a PR is not an archival policy, and an unmerged PR is not upstream main. The sample README permits real samples while CONTRIBUTING still says experiment data stays outside the library; clarify that exception.

This publication is a checksummed mirror, not twelve additional experiments. No hosting or new storage service was created.

Capture next time: task/runner/container revisions, resolved models, seed, roles/routing/budgets, stop reason, complete logs, approved final workspace/patch history, evaluator revision and grade, and hashes of submitted artifacts. Never publish agent homes, credentials, capability links, or protected hidden tests.
