02 / Analysis method

Measure structure, annotate messages,
then inspect cited collaboration claims

1 / PreserveSharedNet JSON and transcript; canonical trace and provenance.
2 / MeasureStructural metrics, regex candidates, and separate agent-only metrics.
3 / AnnotateScout primary/secondary types, earlier replies, addressees, and evidence spans.
4 / JudgeAnnotation-guided candidates; three cited collaboration categories per trace.
5 / InterpretRead original messages; distinguish observed statements from task outcomes.

What was run

36 selected completed analyses

18 substantive offline runs = 9 structural/heuristic + 9 regex. 9 Scout runs produced 70 message annotations and 27 category judgments.

The remaining 9 are optional demo-plugin runs, not an additional validated detector. All 9 facts_v1 entries are unavailable: per-agent execution logs were absent.

What validates / what does not

Strict citations, unvalidated interpretations

Annotations see bounded earlier context, not future messages. Exact spans and original message references are checked; bounded retries reject malformed evidence.

That checks output structure and citation validity, not semantic correctness. Confidence is model-reported, not a calibrated probability.

Evidence labels used throughout: Measured = computed from archived data; Model-judged = saved Scout output; Observed = a visible conversational statement; Reported = teammate context, without an independent grade.

Scout model: openai/gpt-5.4-mini. Eight selected runs use analyzer 2.1.0 / prompt 3; E7 uses 2.0.0 / prompt 2. The 70 annotations include all 11 task/operator posts. No new inference was used to create this report.

Observed

The Verifier and Planner challenge the change to B. The Executor later calls that change a mistake. The conversation ends with agreement on D.

The solo condition reports B and its own PASS ({{GPQA_SOLO_REF}}). The teammate-reported reference is D, without an archived external grade.

Critical chronology caveat

The return-to-D claim precedes FAIL

E9 #7 already reports D before #8 reports B. We cannot infer that the later FAIL caused the earlier reported correction, or reconstruct actual file state from these messages.

A useful challenge/reconsideration episode is not the same as a proven accuracy improvement caused by verification.

Evidence: {{GPQA_REFS}}. A future harness should timestamp artifact versions and actual stop events: the transcript continues after an early PASS despite a stated PASS-based stopping rule.

07 / Limits, decisions, and the next experiment

Turn plausible mechanisms into a controlled,
externally scored pilot before training

Current limits

What this cohort cannot establish

A small, convenience-selected set with repeated tasks, two descriptive solo/team pairs, mixed Scout versions, and partial visibility does not identify general failure rates or causal gains.

There are no independent grades, file-write logs, token/cost records, or validated human labels. Public message span is not active runtime. Task-only silence is unobservable behavior, not a diagnosed stall.

Training and broad reported team experiments are not claimed as completed by this analysis.

Proposed next pilot — not run

Test ownership, not just extra prompting

For coding tasks, compare a solo baseline, a fixed-role team baseline, and the same team with explicit task/artifact claims plus accepted ownership transfer.

Match tasks, model/version, aggregate per-run budget, seeds, and external grader. Keep roles and verifier policy fixed between the two team conditions. Repeat conditions; separate exploratory and held-out tasks.

Start with a feasibility pilot, then set sample size and budget from observed variability; this report does not claim statistical power.

Primary outcome

External task success

Use a task-specific grader and preserve the produced artifacts; do not substitute self-reported PASS.

Mechanism & cost

Ownership + execution evidence

Log artifact writers/versions, ownership transitions, useful versus redundant checks, tokens, elapsed time, and stop events.

Analysis validity

Human adjudication first

Two reviewers independently label sampled episodes. Adjudicate disagreements; assess per-class errors and agreement before treating Scout as a research measure.

Proposed decision gate: only pursue a training target after the intervention improves independently scored outcomes under controlled budgets and the detector's judgments survive human review.

Bottom line: reproducible evidence collection is ready; performance and training claims remain open research questions.Briefing 8 / 8

Appendix B / Measurement and annotation caveats

Task prompts change the metrics;
complete post coverage is not complete text visibility

Measured p95 message length, in words

{{METRIC_ROWS}}
TraceAll postsAgent onlyEvidence

Long operator/task prompts dominate the all-post p95 in these three bundle traces. This does not show that agents sent very long messages. Agent-only E7 metrics are undefined, not invented zeros. Solo dominance is expected from the condition, not evidence of a collaboration failure.

Metric interpretation: adjacency and turn switching are not proof of a handoff or information uptake. Metrics describe visible conversation structure, not task success.

Bounded text and history

Per annotation: up to 6 explicitly cited earlier messages at 2,000 characters each, 12 preceding messages at 500 each, and 8,000 target characters. No future messages. Collaboration: up to 80 candidates at 2,000 characters each.

Appendix D / Reproduction and provenance

Reproduce the report and explore the saved results

1 / Report & saved AgentTrace results

Read HTML/PDF offline, without a server or model key. Rebuild using Python 3.10+: python3 reports/2026-10-16-progress/build_report.py; add --check to verify saved HTML/JSON.

For the interactive UI, clone/install using the repository setup, then make build. From the repository root, with any previous AgentTrace server stopped:

source .venv/bin/activate
export AGENTTRACE_DATA_DIR="$PWD/.agenttrace/teammates"
mkdir -p .agenttrace
mkdir -m 700 "$AGENTTRACE_DATA_DIR" &&
  cp data/teammate-traces/agenttrace.sqlite3 "$AGENTTRACE_DATA_DIR/" &&
  cp -R data/teammate-traces/runs "$AGENTTRACE_DATA_DIR/" &&
  agenttrace

The non-recursive mkdir refuses to overwrite a previous restoration. Never point the API at the committed snapshot. Open http://127.0.0.1:3000/ and data/teammate-traces/batch/links.html.
